## 本地数据迁移

应用启动时，`App/IdentityMigration.swift` 在加载插件前执行一次性迁移；必须先由用户退出旧身份的应用，防止两个版本同时写同一批文件。迁移失败时阻止插件加载与配置写入，展示恢复提示；修复后重新打开会重试。迁移完成标记写入新偏好域，不把旧域加入运行时搜索列表。

- 应用支持目录与缓存改用新命名空间。大模型、图片、录屏等通过文件系统移动，不把内容读入内存，也不复制整套媒体/模型。
- 内置插件记录改用新 ID 和文件名，保留命令 UUID、目标、自定义快捷键、启停状态、安装日期、已初始化/删除的默认模板，以及未知 JSON 字段。语音偏好文件同步换名。
- 已有新文件优先；同名冲突和变更前的插件记录保存在新应用支持目录的 `MigrationBackups/<随机目录>/`，不覆盖任何一方。失败已移动的内容保留在新目录，重试会继续；不存在“失败后清空用户数据”的分支。
- 只导入 `appearance`、`capture.*`、`sharing.*` 应用偏好，不覆盖新域已有值。不导入系统权限状态。身份切换时将共享会话设为停止，用户完成授权后自行启动。
- 默认图片导出目录统一为 `~/Pictures/Untitled`，历史默认目录通过移动合并，相关保存路径随之更新；任意自定义目录及用户文件名/模板不做全局字符串替换。
- 导出索引统一为 `.untitled-exports.json`。默认目录随启动迁移；自定义目录只在下一次显式保存时迁移索引，冲突条目优先保留新索引值。

迁移拒绝直接操作遇到的符号链接；目录合并每次最多处理 100,000 项、深度低于 64 层，JSON 读取上限 16 MiB。预算或权限错误保留数据并提示恢复，不无限遍历或一次性读入媒体。迁移备份应在核对成功后由用户自行整理；历史偏好域也保留作恢复来源，不再参与日常读取。

## Keychain、系统授权与配对

API 密钥与配对密钥仍只存 Keychain，不经文件、清单或日志中转。`Runtime/AppCredentials.swift` 在用户实际读取相应密钥时按需迁移：先查询新 service；不存在才请求访问历史条目，写入新 service 并读回校验成功后才删除旧条目。新条目已存在则优先采用，不用旧值覆盖。写入、验证或系统拒绝访问时不会预先删除旧密钥。

macOS 可能要求用户允许新代码身份访问旧 Keychain；此权限不能绕过。若拒绝或旧代码签名不再可信，重新输入 API 密钥或重新配对即可恢复。成功解除配对会先删除历史导入源，再删除新条目，避免先删新条目后又从旧项恢复。任一步被系统拒绝都会报告错误，不宣称已撤销；用户允许访问后重试，停止共享的意图不变。

**TCC 系统授权无法迁移。** 新 Bundle ID 需要用户在 Untitled 的“应用设置 → 权限管理”中，按实际功能重新授权辅助功能、输入监控、屏幕录制、麦克风或摄像头。不修改 TCC 数据库、不批量重置其他应用权限，也不在启动时申请整套授权。固定签名身份继续使用 `.signing-identity` 或 `UNTITLED_SIGNING_IDENTITY`。

外设共享两台 Mac 都需升级到新身份版本，再由用户启动共享。新 Bonjour 与 TLS 身份不承诺连接旧版本；配对密钥成功导入后可沿用，不能访问旧条目时重新配对。启动迁移不会自动监听、连接、接管输入或恢复采集。

## 驱动升级

应用构建仅生成随包驱动，不安装。用户明确选择升级时运行：

```bash
sudo ./Tools/SharingMicrophone/install.sh install "dist/SharingMicrophone/UntitledMicrophone.driver"
```

安装器验证新包签名与元数据，也核对固定历史路径中的身份；确认后将新旧现有包移至 `/Library/Application Support/com.untitled.app/AudioDriverBackups/` 的 root 私有备份，再装入新包。失败尝试回滚两者，备份不会随临时目录删除。卸载同时移出已验证的历史驱动与新驱动。不会下载或执行包内 helper，不重启音频服务、不修改默认音频设备、不关闭系统安全功能。

方便时重启 Mac，再在会议/录音软件中重新选择 **Untitled Microphone**；新设备 UID 不会伪装成旧驱动。

本次升级实际完成：

- 包含安全保护的最终回归为 **268 项 / 25 组串行测试通过，3 项条件跳过**；40 项听写、文本投递和身份迁移聚焦测试通过。
- 使用与旧版相同的固定 Developer ID 证书生成 Release，启用 Hardened Runtime 与安全时间戳；深层签名校验通过。两端实际运行 `com.untitled.app`、`Untitled` 可执行文件、0.10.0 / build 29，签名团队及代码哈希一致；不是临时签名调试包。
- 严格校验 SSH 主机身份及传输包 SHA-256。先正常退出另一台，再正常退出本机，没有 force quit。备份完成后原子替换 `/Applications/Untitled.app`；保留用户数据，不安装 HAL、不重启系统音频、不更改默认音频设备。
- 本机通过原生导入更新 4 个已安装插件，并核验原有 12 条命令的 UUID、动作、目标、快捷键、启停状态和默认模板历史保留；另一台只更新其已有的外设共享插件。两台的共享 deviceID 保留，不给另一台额外安装未选择的插件。
- 第一次启动后的迁移完成标记及 `sharing.sessionEnabled = false` 均已核验。用户随后确认两端新应用的辅助功能 / 输入监控授权完成，并自行开启共享；再次只读核对时两端已有对端、布局已就绪、麦克风发送 / 接收均关闭。没有用脚本把首次启动意图改为开启。
- 系统授权由用户确认，未读取或改写 TCC 数据库，未导出任何配对或 API 密钥。Keychain 仍由新应用按需处理系统访问询问。

两台的回退快照位于用户私有 `~/Library/Application Support/Untitled Upgrade Backups/<deployment>/`：包含原应用的 `Untitled.previous.app.zip`、应用支持目录、旧偏好导出及 `receipt.json`。旧应用归档经解压和原签名核验后，移除可被误启动的旧 `.app` 备份目录；数据备份保留。不要直接运行历史应用；需要回退时先正常退出新应用，解压并核验旧包，再按原命名空间恢复对应数据。系统权限与 Keychain 不宣称可通过文件快照自动回退。

共享状态的只读核对不等于全部物理验收：接收端 `parked` 持有隐藏 / 解绑租约可能是正常停放，不代表继续转发输入；当前无恢复积压或清理错误。后台触发路径、肉眼残留光标、真实媒体质量及尚未接通的语音适配仍需对应工作流的独立验收，本次没有额外注入测试输入。

## 双机键鼠热修复（0.10.2 / build 31）

用户报告无法继续共享时，只读现场显示：两端已经认证连接、像素布局就绪，但对端因指针漂移保护停用了键鼠，网络连接状态曾掩盖该暂停。代码修复使接收端在建立停放锚点前有界排空已提交的回放，按本机代次拒绝迟到输入，并保留已通过监听的按住状态，避免取消队列中的 key-up 后遗留按键。Hello/心跳可选字段同步键鼠启用状态，只通知、不远程启用；正常归还不再覆盖暂停原因，主界面区分本机/对端暂停。

用户随后明确选择“更新两台”，本次独立执行了正常退出和替换：

- 两端均为 **0.10.2 / build 31**，外设共享通过原生导入更新为 **1.4.1 / minimumHostVersion 0.10.2**。固定 Developer ID、Hardened Runtime、安全时间戳与深层签名通过；两端 CDHash 为 `47ed4312e5c663db64af75680348a8942903a72c`，指定要求与旧应用一致。
