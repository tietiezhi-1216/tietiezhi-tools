# 豆信语音输入

macOS 14+、Untitled **0.10.5+** 的原生语音听写插件。Swift 自行实现豆包网页游客初始化、VoiceGenie WebSocket 与 protobuf 消息，不运行 Python 桥接器、不注入微信或豆包客户端。

## 当前开放范围

**本版允许用户显式开启「实验性实时输入（自行测试）」；尚未完成端到端兼容性验收，不宣称实时输入已验证通过。** `realtimeInputVerified` 仍为 false，旧偏好升级后的自测开关默认关闭；安装、升级和打开面板不会替用户开启。未开启时，普通实时热键仍在权限检查、目标捕获、录音和联网前明确拒绝，不悄悄录音或降级为预览。开启只是允许测试，仍需正常权限；不改用户插件启停或快捷键。微信独立接口尚未接通，不会把微信选项转接豆包。

## 使用

1. 使用包含 `SpeechInput` 原生模块的新版宿主，在商店中导入本插件 ZIP。安装、启用和打开面板不会启动麦克风、初始化游客或申请系统权限。
2. 若自行测试上屏，在插件面板或设置中开启「实验性实时输入（自行测试）」。该明确选择同时开启「实时输入当前应用」，不申请权限、不开始采集；原有时长与快捷键不变。
3. 点击目标应用的可编辑输入框，再用下方快捷键开始。首次听写需要麦克风授权；实时模式另需辅助功能。缺少权限时只定位权限管理，授权后重新执行，不自动录音。
4. 按一下开始 / 再按一下结束，或按住说话 / 松开结束。黑白浮条不抢输入焦点；结束后尝试用豆包最终结果修正本次文字。若回读或焦点异常，自动输入会停止，识别文字仍可在插件面板复制。
5. 面板的「试音（仅预览）」始终不写入其他应用；只需麦克风权限。取消、停用或退出会释放采集与连接，不自动撤回已输入文字。

默认按键均可在右上角「快捷键」中修改：

| 操作 | 默认快捷键 | 行为 |
| --- | --- | --- |
| 切换听写 | **⌃⌥空格** | 开启自测与实时输入后，按一下开始 / 再按一下结束 |
| 按住说话 | **⌃⌥⇧空格** | 开启自测与实时输入后，按住说话 / 松开结束 |
| 取消 | **⌃⌥Esc** | 立即停止采集和连接，保留已输入文字 |

浮条为 **72 × 30 pt** 黑白小胶囊，仅保留居中音量波形；没有图标、状态文字、计时、停止或取消按钮。鼠标穿透，不遮挡底下控件，也不激活主应用或成为 key window。请用原快捷键或插件面板结束 / 取消；停用、卸载、退出和更新时关闭。连接完成前松开按住键也会立即停止麦克风，并在连接就绪后提交已录下的短句定稿，不丢掉开头；点击取消则立即终止，不会稍后重新打开麦克风。快捷键冲突不会覆盖其他绑定，用户清空、编辑或删除的默认操作在升级后保留。操作列表中的「运行」按钮以切换方式测试按住动作，不制造无法松开的按住状态。

## 麦克风选择与采集诊断

- 面板 / 设置提供本机输入设备选择。默认跟随系统默认输入，但每次开始都会解析并明确绑定该设备 UID；选择设备只更改本插件偏好，不修改系统默认设备，也不提前录音。
- 已选择的设备断开时明确拒绝，不偷偷换成另一支麦克风；点击「刷新设备」重新选择。列表最多 128 个设备，只在页面显示、手动刷新和主动开始时查询，不保留后台设备监听。
- 采集来自运行 Untitled 的这台 Mac。对着手机或另一台 Mac 说话，声音不会自动传入；虚拟 / 聚合设备会明确标注，需用户已有相应路由。
- 面板保留本次实际输入名称、PCM 字节数、音频回调次数、原始 RMS 音量峰值 dBFS 和 ASR 更新次数。不保存声音或识别内容；这些计数用于区分「无回调」「纯静音」和「有信号但没有识别」。
- 原先只显示最近一个 20 ms 帧的音量，可能被下一个静音帧覆盖；现在保留每次 50 ms 合并读取之间的峰值。启动后 5 秒仍没有任何音频帧会停止并提示恢复路径；正常有帧的静音不会被当成队列失败。
- 输入队列显式检查协商的 16 kHz 单声道 PCM16 格式和缓冲重入错误，停止 / 销毁时同步等待回调；不以 AudioQueueStart 成功码代替已采到声音。

## 实时识别与最终整理

音频通过 16 kHz、单声道、PCM16 实时发送。使用网页端的 **two-pass ASR** 配置：录音中接收 streaming hypotheses，结束后等待 `ASREnded`、最终结果和 `SessionFinished`，不把中间文字当成成功定稿。

**实时标点限制**：同一 14.81 秒合成样本的三轮对比（原配置、关闭 `enable_trim_punctuation`、省略 `last_post_process`）均得到 35 次非空实时更新，实时稿中 0 次含标点；结束后最终稿包含 9 个标点、67 个 UTF-16 单元。服务的转写内容只在 `text` 字段中，没有被本插件丢掉的另一份带标点实时文字。试验参数没有改善，生产配置保持原样，不用本地规则猜标点。

定稿去重：结束后可能收到多个 ASR 修订，但不再逐个写进目标；冻结中间稿，等权威最终结果完整返回，只调用一次定稿提交。如果已有一个中间写入正在等待确认，先让它安全完成，再串行提交最终稿；相同最终文本不再次改动。目标若忽略或截断长 Unicode 事件，明确停止并保留面板结果，不拆小重发或盲目删除。单个输入事件仍不等于跨应用原子事务，具体编辑器渲染需用户验证。

请先按快捷键结束录音，等待最终结果写入后再发送。若先发送消息、切换焦点或修改文字，输入所有权保护会停止后续替换，插件不会回写已发送内容。当前不能宣称支持逐字即时标点。

最终结果由豆包 ASR 处理标点与数字规范化，并可能纠正中间识别错误。例如合成样本的「明天下午三点」在最终文本中变为「明天下午 3 点」。**这不等于额外大模型润色**：本轮合成样本中的「嗯、那个、然后然后」仍会保留，不能保证删除口头语、纠正事实、改写或总结；插件不会将文本发送给另一模型。

这是非官方网页接口，并非火山引擎开放 API。网页结构、应用标识、模型路由、限额和服务可用性可能变化；无需登录或账号密钥不代表官方承诺免费、无限量或长期兼容。失败不自动更换身份重试，不静默重传录音。

## 输入安全与兼容边界

- 启动时绑定目标进程、焦点元素与原选区，按 **UTF-16** 范围管理本次输入。每次更新前确认焦点、选区和文本仍符合已写入的状态；最终结果只能替换原选区 / 本次听写范围。
- 实时输入模式拒绝安全输入和密码框。目标窗口切换、光标移动、手动编辑、权限撤销或写入失败会停止自动输入并结束采集；已识别文字仍可在面板复制。
- 实时写入仅在用户明确开启自测后开放。文字通过进程定向 CGEvent Unicode 事件输入，AX 只负责范围与回读校验；不再把 AXSelectedText 的成功返回码当作已上屏。中间稿仍按不超过 16 UTF-16 单元的小事件输入，每个确认后才继续；结束后停止提交中间修订，只等最终结果就绪再提交一次。最终变化后缀使用一个受长度预算约束、编码回读校验的 Unicode 事件（最多 32,768 UTF-16 / 64 KiB 文本载荷），不再先缩短到 16 字再分块展开；只覆盖本次拥有的变化范围，不重写用户整框，不用剪贴板。暂不可读时最多重读 700 ms，不重复发字。AX IPC 由会话内串行 worker actor 执行，不阻塞主线程音频发送。
- 换行、Tab、Esc 等控制字符写入时转换为空格，避免触发发送或导航快捷键。原始识别结果仍可在面板查看和手动复制。
- 长串、选区和具体编辑器仍需用户实际验证；不宣称兼容所有 Electron、浏览器或微信输入框。实时模式失败不会静默降级。
- 为校验范围，会暂时读取焦点输入框的文本（最多 131,072 UTF-16 单元），不会把原文、周围文档或其他窗口内容发给豆包。该快照随会话结束释放。
- 插件面板中的试音始终是显式预览。关闭自测开关即重新阻断未验证的实时路径，不改原快捷键或时长；未在听写时不会申请权限或采集。已有仅预览偏好仍不要求辅助功能权限。

跨应用自动化不是原子事务；某些应用的 AX 实现可能延迟或拒绝修改。本实现遇到不一致即停止，不宣称兼容所有编辑器。

## 数据、网络与权限

插件 ID：`com.untitled.doubao-speech-input`。清单声明 `system.microphone`，并把 `system.accessibility` 声明为仅实时输入需要的可选权限。全局快捷键使用 Carbon，不需要输入监控。

仅在显式听写时访问：

- `https://www.doubao.com/chat/`：取得服务端正常分配的新游客设备标识。
- `wss://frontier-audio-web-ws.doubao.com/api/v2/sami/voicegenie`：发送麦克风音频、接收转写。

不读取 Chrome / Safari / Edge 登录资料，不保存或转发首页 Cookie，不持久保存游客设备标识；WebSocket 不携带账号登录凭据。公开网页应用标识不是个人 API Key，因此本版没有密钥设置。

不写入音频、转写历史或识别内容日志。仅在内存中保留最近一次文字，可在面板清除；退出后消失。点击「复制文字」才更改剪贴板。采集使用用户选定的输入设备（默认跟随系统输入），不更改系统默认设备。

偏好设置原子写入宿主应用支持目录的 `Plugins/Preferences/<plugin-id>.dictation.json`，仅包含实时输入开关、实验性实时输入自测开关、时长预算及可选输入设备 UID。UID 只保存在本机私有配置，不发给豆包或写入日志。旧 JSON 未包含自测字段时按 false 解码；已有自测选择保持，缺少设备字段时继续系统默认，不因升级重置。操作和热键仍由宿主插件配置管理。升级保留配置；卸载删除插件操作及本插件偏好。

## 性能与资源预算

- 每个插件实例最多 **1 个录音 / 网络会话**；不并发录音，不加载本地模型。
- 默认每次 **180 秒**，可选择 30 / 60 / 180 / 300 秒；到达上限自动结束录音并请求定稿。
- AudioQueue 使用 3 个 20 ms 输入缓冲区，回调只向锁保护邮箱写 PCM 和音量，不在回调里联网或创建 Task。
- 连接期间暂存最多 **320,000 字节（10 秒 PCM）**，就绪后按 100 ms 分片清空，并把发送邮箱收紧到 **64,000 字节（2 秒 PCM）**。超预算会停止并报错，不无限排队，也不静默丢音频；不为整场会话保留录音，不写录音文件。
- 首页最多 **2 MiB**，单条消息最多 **256 KiB**，听写文字最多 **32,768 UTF-16 单元**；仅保留 64 个近期消息 ID 去重。连接、发送和结束阶段有 15 秒操作看门狗。
- 仅活动会话有 50 ms 合并发送循环、1 秒权限检查 / 网络看门狗；文字写入最多约 7 次/秒。音量条由实际音量驱动，不设置空闲动画时钟。
- 正常完成、取消、断网、权限失效、停用、升级、卸载、退出和对象销毁都会停止并同步销毁 AudioQueue、取消 Task、关闭 WebSocket、清理页面会话与浮条。空闲不保留设备、网络连接或轮询任务。诊断只增加有界计数和峰值，不另存音频；停止后保留这一份统计直到下次会话。

### 协议基线与自测版验证边界

- Swift 原生客户端已用 **14.81 秒本地合成音频**完成两次真实网络验证：录音推流阶段分别收到 **34 / 35 次非空中间更新**，两次都得到 **67 个 UTF-16 单元**的最终文字并正常结束会话，整次各约 17.1 秒。没有访问真实麦克风或跨应用 AX。

- **未测 / 待用户自测**：真实麦克风完整听写、TextEdit / 浏览器 / Electron 最终替换、5 分钟上限、真实断网 / 撤权、多轮真实音频回收趋势、上游限额。
- **未测**：Release 宿主基线 / 峰值 physical footprint、CPU / GPU / 唤醒、真实麦克风首次 / 持续开销及多轮停止后的趋势。预算、单元测试和合成网络成功不能代替性能验收；不宣称性能已合格或无泄漏。

性能复现按 [宿主规范](../../docs/PERFORMANCE.md)：停用其他插件，在同一 Release 构建分别记录宿主空闲、启用但未执行、30 秒与接近 300 秒听写、完成 / 取消 / 停用及 10 轮重复的 footprint、CPU、耗时与回收趋势；同时观察系统音频服务。公开记录仅保留去标识统计，不包含录音、文档或游客参数。
