# 外设共享 1.0.0（主应用 0.9.0+，macOS 14+）

两台 Mac 通过局域网共享键盘、鼠标、麦克风，独立运行，不需要安装 Oink。参考 Oink 的“屏幕边缘键鼠接力 + 应用使用时才采集远端麦克风”体验；**不是 Oink 协议兼容层，也不包含其 GPL 代码**。

## 当前能力

- Bonjour 自动发现、用户手动连接；同一个 256 位随机配对密钥通过 TLS 1.2 PSK / AES-GCM（Apple Network.framework 的外部 PSK 套件） 认证加密，不接受证书认证作为密钥的替代。
- 双向接力：任一 Mac 都可以将自己的键鼠切换到另一台。两端必须明确允许；同一时刻只有一方控制，不是把每次按键同时广播给两台。
- 配置左、右、上、下四种相对位置；推过屏幕边缘切换，从进入边缘移回可返回。支持标准按键、修饰键、鼠标移动/点击/多击/拖动和像素滚轮。
- 按 `⌃⌥⌘K` 切换；按 `⌃⌥⌘Esc` 紧急返回。目标设备的实体键鼠操作也可夺回本机控制。可以在插件的“快捷键”面板自行添加宿主全局操作。
- 麦克风独立于键鼠控制目标。A 允许发送、B 开启接收且 B 的应用实际使用 `Tietiezhi Microphone` 时，才在 A 检查权限并采集所选实体麦克风。A 的应用可以同时使用其实体麦克风；双方也可以各自发送自己的实体麦克风。
- 自带独立 HAL 虚拟输入与隐藏 Feed 输出，不要求 BlackHole；**驱动需要用户明确使用管理员命令安装**，发送端不必安装。
- 禁用插件、卸载插件、退出、断线/心跳超时、锁屏和睡眠时释放输入、恢复光标与停止音频；不会自动重连或自动恢复采集。
- 安装/启用插件和打开页面不会自动监听网络、请求权限、采集输入、安装驱动或启动麦克风。

## 性能与资源

安装、启用与打开面板不启动采集；显式共享后按输入事件工作。网络帧正文上限 256 KiB，解码缓冲有上限，接收端音频待播放帧数限制为 9600，队列满时丢弃后续音频，避免无限积压。这些只是局部边界，不代表整个插件的内存预算。

按[性能规范](../../docs/PERFORMANCE.md)区分连接空闲、持续键鼠输入、仅麦克风和两者同时运行，分别观察宿主、HAL 驱动及系统音频进程。测试断线、停止、睡眠、禁用后的清理与多轮重连趋势。协议缓冲、音频积压和服务停止已有自动测试；真实双机持续运行、能耗与完整链路性能尚未量化，不能据此宣称低延迟或低开销已验收。

## 安装开发版本

新增原生能力需随主应用编译，不能将此 ZIP 单独安装到旧版主应用。

```bash
./scripts/build-app.sh release
python3 scripts/package-plugins.py --tag v0.9.0
```

产物：

- `dist/release/Untitled.app`
- `dist/plugins/peripheral-sharing-1.0.0.zip`
- 应用内 `Contents/Resources/PeripheralAudio/` 包含已构建驱动、许可、说明和显式安装脚本。

将与设备架构匹配的 0.9.0 主应用和 ZIP 放到两台 Mac，在商店点“从 ZIP 安装…”。源码构建结果为本机架构；需要在 Intel 上运行时请相应构建主应用。商店目录需等 GitHub Release 的主应用/插件资产实际发布后再更新，不能把未发布地址写入在线商店。

键鼠拦截/模拟输入需要**非 App Sandbox 的应用构建**，推荐使用 `build-app.sh` 产物。Xcode 与命令行构建均不启用 App Sandbox，保留 Hardened Runtime 与系统隐私授权。不要绕过系统授权、修改 TCC 或关闭系统安全机制。

## 双机配对与键鼠

1. 让两台 Mac 接入同一可信局域网。测试时先关闭 Oink、通用控制等可能争用键鼠的共享功能。
2. A 在插件内生成新配对密钥，点击复制，通过可信渠道传给 B；B 粘贴后保存。同一密钥保存在两台设备自己的钥匙串，不写入插件 JSON、日志或源码。
3. 两端均点击“启动共享”，允许 macOS 的本地网络访问及防火墙询问。在其中一台的发现列表点“连接”；不要同时发起连接。
4. 两端开启“允许此连接共享键盘与鼠标”。缺少权限时宿主定位“应用设置 → 权限管理”，由用户主动授权辅助功能、输入监控，然后重新开启该选项。
5. 例如 B 在 A 右边：A 选“右侧”，B 选“左侧”。将指针推过 A 的最右侧外边缘，或点击“控制另一台 Mac”。从 B 的左边缘推回，或用紧急返回按键返回 A。

不会显示或传输远端屏幕；你需要能直接看到两台 Mac 的显示器。多显示器按活动显示器的全局外接矩形计算入口，并将落点限制到真实显示器，首版不提供任意拓扑/屏幕间隙的可视化编排。

## 麦克风同步

### 在接收端明确安装一次

插件中打开“驱动与使用说明”，显示安装文件。在终端执行选定操作：

```bash
# 发行包：文件路径请替换为实际路径
sudo "/path/to/PeripheralAudio/install.sh" install
# 源码构建
./scripts/build-sharing-microphone.sh
sudo ./Tools/SharingMicrophone/install.sh install "dist/SharingMicrophone/TietiezhiMicrophone.driver"
```

方便时重启 Mac，使系统加载驱动；安装器**不会**重启系统音频或打断当前通话。不自动修改系统默认输入或输出。公开分发须使用 Developer ID 签名与公证；本地自签/临时签名不能保证在另一台 Mac 加载。

### 使用

1. A 选择实体麦克风，开启“允许将本机麦克风同步给对端”。
2. B 开启“在本机使用对端麦克风”。
3. B 的会议/录音软件选择 **Tietiezhi Microphone** 为输入，而不是本机内置麦克风。
4. 应用开始读取时，A 才检查麦克风权限；缺失时由 A 的统一权限管理处理。授权后点“检查 / 重试”，不要以为授权会自动开始共享。
5. A 显示正在发送状态，B 显示接收状态。停止读取、关闭选项、断线或锁屏后停止采集。共享声音只送往隐藏 Feed，不回退到扬声器，避免声反馈。

如果只共享键鼠，无需安装任何音频驱动。如果目标软件长期保持输入打开，即使静音/未开会也可能仍被系统视为使用麦克风；要彻底停止采集，请关闭本插件的发送开关或停止共享。

### 卸载驱动

```bash
sudo "/path/to/PeripheralAudio/install.sh" uninstall
# 方便时重启 Mac
```

卸载插件会停止共享，但不擅自申请管理员权限删除系统驱动。驱动的安全安装边界、设备 UID、许可与构建说明见 [Tools/SharingMicrophone/README.md](../../Tools/SharingMicrophone/README.md)。

## 安全与首版边界

- 密钥是授权凭据，不是短 PIN；只给可信设备。复制后 60 秒若剪贴板未变化则清除。重新配对需先停服务，并在两端替换密钥；解除配对删除本机钥匙串项。
- Bonjour 名称只用于发现；收到名字不等于认证。TLS 成功且设备握手完成后才接受控制请求，且键鼠/麦克风仍需本机显式开关。
- 当前 TLS 1.2 的纯 PSK 套件不提供前向保密；配对密钥日后泄露可能影响已被录制的历史流量。请保管好密钥并仅在可信局域网使用；不宣称具备前向保密。
- 消息长度、输入类型/数值、音频大小与有限采样值均校验；缓冲有上限，网络拥塞时丢弃过时实时音频，不丢失后无限积压键盘释放事件；超过安全上限直接断开。
- 原生事件拦截不等于 USB 透传：不支持任意 USB 设备、摄像头、耳机/系统声音共享、剪贴板、文件拖放、多指手势、特殊媒体键、Windows、移动端或互联网中继。
- macOS 安全输入（密码字段等）、锁屏、登录窗口不受支持；不能远程解锁设备。
- 麦克风使用单声道 48 kHz Float32 PCM、有界缓冲和掉帧/补零；不承诺专业时钟同步、无丢包、专业低延迟或长期音质稳定性。
- 自动测试覆盖协议、边缘计算、权限拒绝、生命周期和 TLS 回环；驱动测试不安装到 HAL。**仍需真实双机键鼠、会议软件麦克风、断网/锁屏、多客户端及长期稳定性验收，不宣称已达到 Oink 全量成熟度。**
