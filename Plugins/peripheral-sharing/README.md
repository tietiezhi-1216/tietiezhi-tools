# 外设共享 1.4.2（Untitled 0.10.5+，macOS 14+）

两台 Mac 独立共享键盘和鼠标，不需要安装 Oink。当前产品先聚焦键鼠；已有麦克风实现保留为开发代码，暂不提供日常入口。**不是 Oink 协议兼容层，也不包含其 GPL 代码**。

## 设备布局

主页面是无界画布：两台 Mac 都可自由拖放，拖空白或双指滚动可平移，双指捏合/右下角按钮缩放，居中按钮显示全部设备。仅在接近接触边缘时轻度吸附，不再提供固定四向槽位。排列经认证连接镜像同步，并确认同一布局版本后才允许接力；只编辑布局不会开启网络或输入。

卡片使用主屏当前 framebuffer 像素尺寸（`CGDisplayMode.pixelWidth/pixelHeight`），不是 Retina 逻辑点，且两台设备共用同一个缩放比例，不把宽度强制设成一样。卡片标明真实分辨率；布局模型和输入射线同用像素坐标。旧版 200 单位布局会在取得两端像素信息后对称迁移，保留方向、错位和间隙；新版协议 v3 收到实际尺寸并确认布局后才允许接力，旧端降级为原方向协议，不发送其无法理解的像素布局。

边缘穿越是默认行为，没有开关。日常界面只保留画布和一个“共享”总开关，开启即启用键鼠；不再显示键鼠选择、返回按钮、快捷键说明或麦克风入口。安全返回快捷键和菜单停止功能仍然保留。穿越按真实排列中的屏幕区间和移动方向投射；错位屏幕只在可到达区段接力，返回位置也按布局映射。画布不是远程画面，单台 Mac 的多屏仍使用其全局外接矩形。配对/地址仅在右上角按需出现，技术与诊断工具不进入日常界面。

应用与新驱动显示名统一为 **Untitled / Untitled Microphone**。0.10.0 起宿主使用 `com.untitled.app`，内置插件使用 `com.untitled.*`；历史身份仅用于显式迁移，不保留运行时别名。迁移保留设备 ID 值、配对、布局和端点，但首次身份迁移不自动开始共享，系统权限需重新授权；细节见[身份迁移说明](../../docs/IDENTITY-MIGRATION.md)。旧版已安装音频驱动不会静默替换。

## 启动与连接

- 只有你实际开启过“共享”，才在普通退出、应用更新后重开时恢复；安装或单纯启用插件不会产生恢复意图。
- 启动后若对端尚未就绪，自动使用记住的地址等待/重试，最多两分钟；只需一方主动连接。已建立会话断线后不自动重新夺取控制或恢复麦克风。
- 手动关闭共享、停用/卸载插件、锁屏或睡眠会清除恢复意图。解锁后仍需明确开启。
- 不设置开机启动、不安装后台守护程序，不绕过键鼠权限。运行状态仅写入用户私有缓存 `com.untitled.app/SharingState/status.json`，内容为连接、布局与计数，不含配对密钥、按键内容、录音或屏幕。

## 当前能力

- Bonjour 自动发现、用户手动连接；同一个 256 位随机配对密钥通过 TLS 1.2 PSK / AES-GCM（Apple Network.framework 的外部 PSK 套件） 认证加密，不接受证书认证作为密钥的替代。
- 双向接力：任一 Mac 都可以将自己的键鼠切换到另一台。两端必须明确允许；同一时刻只有一方控制，不是把每次按键同时广播给两台。
- 在无界画布自由配置设备位置、错位与间隙，新版对端同步镜像布局；推过屏幕边缘切换，从进入边缘移回可返回。支持标准按键、修饰键、鼠标移动/点击/多击/拖动和像素滚轮。
- 按 `⌃⌥⌘K` 切换；按 `⌃⌥⌘Esc` 紧急返回。目标设备的实体键鼠操作也可夺回本机控制。可以在插件的“快捷键”面板自行添加宿主全局操作。
以下麦克风能力仅保留在开发实现中，当前主界面不开放：

- 麦克风独立于键鼠控制目标。A 允许发送、B 开启接收且 B 的应用实际使用 `Untitled Microphone` 时，才在 A 检查权限并采集所选实体麦克风。A 的应用可以同时使用其实体麦克风；双方也可以各自发送自己的实体麦克风。
- 自带独立 HAL 虚拟输入与隐藏 Feed 输出，不要求 BlackHole；**驱动需要用户明确使用管理员命令安装**，发送端不必安装。
- 禁用插件、卸载插件、退出、断线/心跳超时、锁屏和睡眠时释放输入、恢复光标与停止音频；不会自动重连或自动恢复采集。
- 安装/启用插件和打开页面不会自动监听网络、请求权限、采集输入、安装驱动或启动麦克风。

## 后台触发、光标停放与故障恢复（Untitled 0.10.0+）

只有发送端实际取得前台、事件监听有效、鼠标解除关联和隐藏均成功后才转发输入。主界面在后台时，通过同一签名应用中的 1×1 隐形捕获窗口和公开 LaunchServices 激活请求取得所需资格，暂时藏起原有普通窗口，避免把主面板带到前面；这不是完全不改变进程前台状态，也不代表菜单栏常驻自动获得前台资格。接管期间 Untitled 临时保持本机前台，归还时验证原应用已恢复，再恢复原窗口排列；如果你主动切换前台，不会反复抢回。检测到本机指针漂移、未知输入注入、监听失效、权限撤销或前台丢失，会停止新增转发并暂停键鼠，而不是让两个屏幕跟随同一只鼠标。

新版对端通过 `cursorParking` 协商生命周期能力，每次交接使用独立 UUID。接收准备先不移动指针，只有源端成功取得捕获租约并提交后才显示入口光标；旧对端不接收不认识的提交帧。正常从对端越回时，对端先取得光标停放租约并隐藏旧指针，再归还源端，不再把旧箭头留在交接边缘。急停/取消与正常越回区分，旧会话的输入、提交、归还不能影响新会话。

停放端出现真实本机输入时，立即释放隐藏/解绑，取消仍在准备的交接；首次输入只在原应用焦点确认后回放。临时队列最多 128 个事件，鼠标移动合并，不记录键码或内容。停止、断线、队列溢出或焦点被另一个应用接走会废弃整批待回放内容，避免向错误应用输入；这种失败状态不承诺无丢键。下一次接收也等待焦点恢复才确认。物理移动、滚轮、按键、拖动及释放都可夺回本机控制。

鼠标资源按成功取得的项逐一恢复；只平衡本进程自己的隐藏计数。独立于主线程的监护会先撤销旧租约，再尝试恢复鼠标，失败时保留清理责任并禁止新接管。截止时间在转发门和心跳更新处同样检查，不依赖计时器先获得调度；发送编码后还会再次检查。监护不持锁等待任意发送回调，已经提交的在途数据不能撤回。CG 恢复仍依赖 WindowServer 响应，不承诺系统服务无响应时硬实时恢复。它不使用 root 事件拦截、不修改 TCC、不调用私有 WindowServer 接口。

开发者内部可显式运行“本机光标接管测试（10秒）”；0.9.4 起日常插件界面不再暴露该诊断入口。测试会先停止共享，3秒后只在本机临时接管；仅记录状态、CG 错误码、移动次数和最大指针漂移，不保存按键、路径或音频，绝不发送网络输入。测试有不可续期的十秒截止，`⌃⌥⌘Esc` 可提前结束。没有真实非零移动的轮次标为未完成；位置锁定仍须你确认测试时光标隐藏、结束后恢复。最近一次汇总保存在用户私有缓存 `com.untitled.app/SharingDiagnostics/cursor-test.json`。

单元测试使用注入的光标/前台后端，不会真正锁定测试机器的鼠标。测试通过不等于真实物理发送端或双机接力已经验收。

### 0.10.2：异步回放与暂停状态修复

`CGEvent.post` 不会同步完成系统回放。新实现取得停放租约前最多等待 250 ms，让已提交接收事件经过自身监听，并同步最后接收位置；超时拒绝交接，不放宽 0.5 点漂移保护。回放带本机交接代次，监听有效时丢弃旧代次的迟到输入，防止它移动新租约的锚点。释放计划取“已提交”和“已通过监听”的按住状态并集，不能因丢弃迟到 key-up 留下已送达的按键或按钮。

Hello/心跳新增可选 `keyboardEnabled` 状态，旧端可忽略，缺失表示未知。暂停只通知、不远程启用：任一端保护暂停后，另一端明确显示“对端已暂停”，需用户在暂停的 Mac 上重新开启共享。网络连接仍存在不再掩盖键鼠停用原因。缺失新字段的旧端继续按原交接校验工作，不凭未知状态拒绝连接。

新增回归覆盖延迟回放、旧代次、取消、超时、积压和清理释放，全部使用 fake CG/焦点与隔离配置。构建、安装或自动测试通过不代表原故障已完成物理验收，真实双机复现与视觉效果仍需新版本普通使用确认。

### 0.10.5：交接时序与真实隐藏

本机独立、短时视觉验证中，用户确认系统 `CGDisplayHideCursor` 能真正隐藏并正常恢复；透明 `NSCursor` 和后台微型覆盖窗没有达到同等视觉效果，因此不采用这两种替代。该孤立试验不是生产双机验收。新版激活路径等公开 LaunchServices 请求完成、隐形窗口确实成为 key window，并经过一次稳定的主线程调度后才请求系统隐藏；不再仅因前台 PID 改变就提前取得隐藏租约，也不累加 hide 调用掩盖问题。锚点在解绑/隐藏成功后采样，之后仍保留原有 0.5 点漂移保护。

源端取得捕获资格与目标恢复/准备接收改为并行，只有两者都完成、交接 ID 仍有效并提交后才开始网络转发。准备期间鼠标移动只合并为一个有界向量（每轴最多 4096），不逐帧积压；按键、按钮或滚轮会取消交接，等待原应用焦点确认后按原有 128 事件预算恢复真实本机输入，不向未就绪的对端发送。已提交的本机恢复事件也等待自身监听确认后才允许新一次切焦点。

正常接收和确认返回不再统一等待 650 ms，方向与几何边界判断仍保留；失败/急停继续有界退避，避免在边缘反复发送请求。私有汇总增加激活、取得租约和排空回放的实际耗时，不记录按键或路径；尚未取得新版本的真实双机延迟与视觉反馈，不宣称无停顿或残留已解决。

## 性能与资源

安装、启用与打开面板不启动采集；显式共享后按输入事件工作。网络帧正文上限 256 KiB，解码缓冲有上限；接收事件元数据最多 512 项，清理释放最多 288 项，本机恢复回放元数据最多 128 项；等待转发的鼠标向量只有一项，交接等待最多 250 ms，仅在交接期间等待，不增加空闲轮询。接收端音频待播放帧数限制为 9600，队列满时丢弃后续音频，避免无限积压。隐形焦点窗口最多一个，激活/还原验证使用有界 600/800 ms 等待，不在停止后保持轮询；看门狗仍只在持有租约/恢复责任时工作。新增焦点机制已做单机真实激活与原 PID 还原验证，不操作光标；完整双机视觉与首键落点仍需正常使用验收。没有新的完整 footprint/CPU/GPU 基线测量，不宣称性能已验收。这些只是局部边界，不代表整个插件的内存预算。

按[性能规范](../../docs/PERFORMANCE.md)区分连接空闲、持续键鼠输入、仅麦克风和两者同时运行，分别观察宿主、HAL 驱动及系统音频进程。测试断线、停止、睡眠、禁用后的清理与多轮重连趋势。协议缓冲、音频积压和服务停止已有自动测试；真实双机持续运行、能耗与完整链路性能尚未量化，不能据此宣称低延迟或低开销已验收。

## 安装开发版本

新增原生能力需随主应用编译，不能将此 ZIP 单独安装到旧版主应用。

```bash
./scripts/build-app.sh release
python3 scripts/package-plugins.py --tag v0.10.5 --plugin peripheral-sharing
```

产物：

- `dist/release/Untitled.app`
- `dist/plugins/peripheral-sharing-1.4.2.zip`
- 应用内 `Contents/Resources/PeripheralAudio/` 包含已构建驱动、许可、说明和显式安装脚本。

将与设备架构匹配的 0.10.5 或更高版本主应用和 ZIP 放到两台 Mac，在商店点“从 ZIP 安装…”。源码构建结果为本机架构；需要在 Intel 上运行时请相应构建主应用。商店目录需等 GitHub Release 的主应用/插件资产实际发布后再更新，不能把未发布地址写入在线商店。

键鼠拦截/模拟输入需要**非 App Sandbox 的应用构建**，推荐使用 `build-app.sh` 产物。Xcode 与命令行构建均不启用 App Sandbox，保留 Hardened Runtime 与系统隐私授权。不要绕过系统授权、修改 TCC 或关闭系统安全机制。

## 双机配对与键鼠

1. 让两台 Mac 接入同一可信局域网。测试时先关闭 Oink、通用控制等可能争用键鼠的共享功能。
2. 首次连接时，在右上角生成配对码，复制给另一台 Mac 保存；已有配对无需重复配置。同一密钥保存在两台设备自己的钥匙串，不写入插件 JSON、日志或源码。
3. 两端均点击“启动共享”，允许 macOS 的本地网络访问及防火墙询问。在其中一台的发现列表点“连接”；不要同时发起连接。
4. 开启共享即启用键鼠，无独立选择。缺少权限时由宿主定位统一权限管理，用户主动授权后重新开启共享；不绕过系统授权。
5. 在画布自由排列两台设备，另一端自动镜像；例如 B 放在 A 右边，可保留上下错位。将指针推过 A 的最右侧对应区段，从 B 的左边缘推回；紧急返回按键仍有效。

不会显示或传输远端屏幕；你需要能直接看到两台 Mac 的显示器。当前卡片按每台 Mac 的主屏像素显示；输入仍按活动显示器的全局外接矩形计算入口，并将落点限制到真实显示器。多屏混合 DPI 的逐屏拓扑不在本版范围；单台 Mac 内部的显示器仍由系统设置排列。

## 麦克风同步（开发实现，日常入口暂未开放）

### 在接收端明确安装一次

以下为先前开发版本的安装/验证参考，不代表当前 UI 已开放或真实 HAL 接入已验收。只有用户明确恢复音频工作并授权管理员操作后，才执行选定操作：

```bash
# 发行包：文件路径请替换为实际路径
sudo "/path/to/PeripheralAudio/install.sh" install
# 源码构建
./scripts/build-sharing-microphone.sh
sudo ./Tools/SharingMicrophone/install.sh install "dist/SharingMicrophone/UntitledMicrophone.driver"
```

方便时重启 Mac，使系统加载驱动；安装器**不会**重启系统音频或打断当前通话。不自动修改系统默认输入或输出。公开分发须使用 Developer ID 签名与公证；本地自签/临时签名不能保证在另一台 Mac 加载。

### 使用

1. A 展开“麦克风”，开启“共享本机麦克风”并选择实体输入。
2. B 开启“在本机使用对端麦克风”。
3. B 的会议/录音软件选择 **Untitled Microphone** 为输入，而不是本机内置麦克风。身份升级后请显式更新驱动并重新选择输入设备；不再使用旧驱动身份。
4. 应用开始读取时，A 才检查麦克风权限；缺失时由 A 的统一权限管理处理。授权后点“检查 / 重试”，不要以为授权会自动开始共享。
5. A 显示正在发送状态，B 显示接收状态。停止读取、关闭选项、断线或锁屏后停止采集。共享声音只送往隐藏 Feed，不回退到扬声器，避免声反馈。

如果只共享键鼠，无需安装任何音频驱动。如果目标软件长期保持输入打开，即使静音/未开会也可能仍被系统视为使用麦克风；要彻底停止采集，请关闭本插件的发送开关或停止共享。

### 卸载驱动

```bash
sudo "/path/to/PeripheralAudio/install.sh" uninstall
# 方便时重启 Mac
```

卸载插件会停止共享，但不擅自申请管理员权限删除系统驱动。驱动的安全安装边界、设备 UID、许可与构建说明见 [Tools/SharingMicrophone/README.md](../../Tools/SharingMicrophone/README.md)。

## 安全与首版边界

- 密钥是授权凭据，不是短 PIN；只给可信设备。复制后 60 秒若剪贴板未变化则清除。重新配对需先停服务，并在两端替换密钥；解除配对删除本机钥匙串项。
- Bonjour 名称只用于发现；收到名字不等于认证。TLS 成功且设备握手完成后才接受控制请求，且键鼠/麦克风仍需本机显式开关。
- 当前 TLS 1.2 的纯 PSK 套件不提供前向保密；配对密钥日后泄露可能影响已被录制的历史流量。请保管好密钥并仅在可信局域网使用；不宣称具备前向保密。
- 消息长度、输入类型/数值、音频大小与有限采样值均校验；缓冲有上限，网络拥塞时丢弃过时实时音频，不丢失后无限积压键盘释放事件；超过安全上限直接断开。
- 原生事件拦截不等于 USB 透传：不支持任意 USB 设备、摄像头、耳机/系统声音共享、剪贴板、文件拖放、多指手势、特殊媒体键、Windows、移动端或互联网中继。
- macOS 安全输入（密码字段等）、锁屏、登录窗口不受支持；不能远程解锁设备。
- 麦克风使用单声道 48 kHz Float32 PCM、有界缓冲和掉帧/补零；不承诺专业时钟同步、无丢包、专业低延迟或长期音质稳定性。
